## 行政摘要

### 機構與觸發因素

Vertex Peak Financial Technologies Limited（駿峰金融科技有限公司）是一間香港保險科技及金融數據服務公司：作為獲證監會發牌的財富管理軟件供應商，向香港及澳門 260 間保險經紀銷售軟件即服務（SaaS）平台，該平台約有 14,000 個終端用戶席位。公司共有 160 名員工，分別派駐沙田香港科學園總部、觀塘旗艦服務中心、灣仔交付辦公室及澳門代表辦事處，並由六名長期在家工作的員工及約四十名需要遙距存取的外勤銷售人員支援。其資訊科技部門只有五人，而客戶受香港保險業監管局監管，這使可證明的最大特權限制、可審計性及客戶資料保護成為合約事項，而非單純的良好實務。

本項目的業務觸發因素，是與一個經紀集團新簽訂的合約，其盡職審查問卷訂立五項條件：將平台生產鏈與一般辦公室用戶隔離；具備文件記錄的最大特權限制存取，並留存管理操作審計軌跡；使用憑證式認證而非共用密碼的加密遙距存取；為面向客戶的網頁層提供有文件記錄的復原及故障轉移行為；以及證明網絡變更是透過經審閱、可重複的設定套用，而非人手操作。現有環境 —— 一個單一扁平辦公室網絡，非正式地延伸至另外三個地點 —— 五項條件無一符合。本項目就是網絡工程工作流對這項差距的回應。

### 將建置的內容

交付成果是一套完整、可運作並具文件記錄的企業網絡，圍繞題目單張所列的五條技術線組織而成。

- **Microsoft Server Networking and Network Services。** 單一 Active Directory Domain Services 樹系及網域（`vertexpeak.fyp.lab`，NetBIOS `VERTEXPEAK`），總部設兩台網域控制站，觀塘設一台唯讀網域控制站，具備據點感知的組織單位結構、分層管理群組、AD 整合 DNS、具故障轉移的 DHCP、Active Directory Certificate Services、群組原則基線及審計原則；財務、工程及銷售共用資料夾上的 File Server Resource Manager 配額、檔案篩選及儲存報告；向平台層提供的 iSCSI LUN；以及帶 IKEv2 憑證認證遙距存取的 Routing and Remote Access Service，並由 Network Policy Server 授權。
- **Linux Server Administrations。** 一對 Nginx 反向代理，負責終止 TLS 並重新加密至應用層，並以一對 Keepalived VRRP 及浮動虛擬位址提供備援；一對 nftables 出口過濾器以內聯方式部署，作為對外流量的唯一瓶頸點，執行狀態式過濾、位址轉換及丟棄記錄；一台 OpenVPN 伺服器，具備完整的 Easy-RSA 公鑰基礎架構，以及一條獨立連接灣仔辦公室的 WireGuard 隧道；一對 WordPress 內容節點；以及套用於每台 Linux 客體的強化 Ubuntu 基線。
- **Cisco Networking。** 三層式 Packet Tracer 拓撲，總部與觀塘之間在單一區域 0 內運行 OSPF，澳門辦公室及舊有區段使用 EIGRP，並僅在一個路由器上以路由標籤控制重新分佈；與模擬中轉供應商的基本 eBGP，另有第二個供應商連線及前綴控制；具明確根橋及接取埠保護的 Rapid Spanning Tree Protocol；HSRP 閘道備援；以及一台 Cisco ASA 周邊防火牆，以存取清單、NAT 及連接灣仔的站對站 IPsec 隧道實現 DMZ 邊界。
- **Network Automation。** 一個由 Git 追蹤的儲存庫，內含 PowerShell 指令碼、Ansible 手冊、角色及 Jinja2 範本，加上 Bash 強化及維運指令碼，全部由單一控制節點執行；手冊以同一份清單同時設定 Linux 及 Windows 資產；冪等性是硬性要求，並以第二次執行報告無變更來證明。
- **AI Network Management。** 一個代理執行環境，具備嚴格唯讀、由四項已聲明工具組成的工具介面，可接收警示、將其與介面及認證證據相互關聯，並產出一份分流備註及一項供人手審閱的*建議*設定變更。設計上不存在寫入路徑，而示範亦以已聲明範圍的概念驗證形式呈現。

### 將如何建置

整個環境均為虛擬。完全沒有實體網絡硬件：沒有路由器、沒有交換機、沒有防火牆、沒有存取點、沒有佈線，亦無須訂購任何東西。虛擬機資產包括**十九台虛擬機 —— 九台 Windows Server 客體及十台 Ubuntu Linux 客體 —— 運行於一部虛擬化管理程序主機之上**（`vpnz-hvhost01`，即小組成員擁有的實體機器）。建議使用的虛擬化管理程序為 **VMware Workstation Pro 17.6.2**，原因是其 Virtual Network Editor 支援任意僅主機網路並可獨立切換 DHCP，這正是分段設計所需；伺服器作業系統的評估授權，以及其他每個元件的免費或學術授權，意味無須購買任何軟件。虛擬機的區段隔離由獨立的僅主機虛擬網路提供，並禁止使用橋接模式，使實驗室永遠不會連接校園或家居網絡。Cisco 層建置於 **Cisco Packet Tracer** 之中，用以模擬第 2 層及第 3 層拓撲、路由協定及防火牆原則 —— 模擬器的限制已明確說明，任何模擬量測結果均不會以真實世界數據呈現。

### 將如何驗證

驗證與建置同時設計，而非事後補做。五條線中的每項技術均追溯至一個編號測試個案，設計中的每個信任邊界均帶有識別碼，而交付的環境必須能從乾淨主機重現。驗證方法包括：來自模擬器的協定證據（OSPF、EIGRP 及 BGP 的鄰居及拓撲輸出，鏈路故障前後的 Spanning Tree 輸出，防火牆工作階段及丟棄輸出）；來自虛擬資產的服務層證據（目錄複寫狀態、配額及檔案篩選的實際執行、LUN 掛載、VPN 用戶端連線詳情、連接埠矩陣的可達性及拒絕）；故障轉移證據（終止 Keepalived 主節點，並擷取虛擬位址在服務持續回應期間轉移的過程）；自動化證據（第二次手冊執行報告無變更）；監控證據（儀表板及至少三個警示顯示觸發及解除）；以及負面證據，其被視為同等重要 —— 每個區域邊界均須顯示拒絕不應跨越該邊界的流量。

### 將交付的內容

兩項交付成果，重要性相等。第一項是**可運作的技術環境**：內含完整拓撲及其路由、交換及周邊原則均已運作的 Packet Tracer 專案檔；按固定軟件版本建置的虛擬機資產；正在運行的目錄、檔案、儲存、遙距存取、代理、過濾、隧道及監控服務；以及能夠重建及驗證該狀態的自動化儲存庫。第二項是題目單張所要求的**文件集** —— 發現、手冊、建置步驟、螢幕擷取、驗證及參考資料 —— 並組織為設計文件、逐項技術的建置操作手冊、附有已執行測試記錄的測試計劃、證據庫、參考資料庫，以及一份可追溯性矩陣，將題目單張所列的每項技術對應至報告的某一節及某個測試個案識別碼。在指導老師面前進行的示範及答辯構成交付的第三部分：環境以運作狀態展示，其中一個元件被刻意破壞並修復，而結果須以證據作答辯。

### 對機構的價值及與標準的對應

對 Vertex Peak 而言，成果是能夠以證據而非聲稱來回答客戶的盡職審查問卷：生產流量與用戶流量分隔、可在目錄及檔案系統中展示的最大特權限制、管理操作的審計軌跡、憑證式加密遙距存取、面向客戶層的有文件記錄故障轉移，以及經審閱、受版本控制的變更流程。對學生而言，成果是一份達作品集水平的成果物，以企業規模組裝，但在四人小組於十二週內實際可交付的資源範圍之內。

本項目對應 **WorldSkills Occupational Standards 2026**（技能 2447，WorldSkills Shanghai 2026 版）中的 *IT Network Systems Administration* 標準。該標準的評估結構為六個加權部分 —— 工作組織與管理 5%、溝通及人際技巧 5%、資料傳輸網絡 25%、網絡與系統運作 25%、基礎架構自動化 15% 及故障排解 25% —— 合計 100%。本項目**直接發展該加權結構的 95%**：範疇 1、範疇 3、範疇 4、範疇 5 及範疇 6。範疇 2 僅透過本項目的書面及口頭溝通義務間接發展，這一點是披露而非掩飾。相比之下，AI Network Management 線在該標準中**完全沒有涵蓋**：2026 版中「agentic AI」、「OpenClaw」、「MCP」或任何形式的人工智能出現次數為零。因此該線以超越標準的創新形式呈現，並以標準本身的範疇 1 要求作為理據：資訊科技專業人員須跟上 IT 系統的變化速度、運用周全而有效率的研究方法，並樂於嘗試新方法及擁抱變革。本計劃書不會聲稱符合 AI 相關規定，因為這樣的聲稱並不真確。

### 1.2 問題陳述

Vertex Peak 今日營運的環境是因累積而成，而非因設計而成，其每一項缺失都可追溯至本項目所處理的五條技術線之一或多條。以下按檢討時會發現的情況陳述這些缺失，並在括號內指出必須解決各項缺失的技術線。

**身分及 Windows 平台缺失（L1 —— Microsoft Server Networking and Network Services）。** 機構沒有單一身分。觀塘、灣仔及澳門據點的員工在各自管理的機器上持有本機建立的帳戶，因此離職者的存取權僅在據點管理員記得移除時才會被移除，亦無任何權威記錄顯示誰持有什麼。總部現有的網域從未擴展為據點感知結構，因此複寫拓撲、登入本地性及委派管理均未經設計。檔案存取失控的程度，正是盡職審查問卷所關注的那種：財務、工程及銷售共用資料夾有權限但沒有配額、沒有檔案篩選，也沒有儲存報告，因此個人可以填滿整個磁碟區，而事後無人能證明誰持有或派發過什麼。軟件即服務平台是公司唯一產生收入的資產，卻沒有自己的區塊儲存，而是依賴附加於個別虛擬機內的磁碟，因此一個節點失效便會連同其資料一同失去。遙距存取是老化設備上的共用密碼 VPN，直接不符合第三項盡職審查條件。

**Linux 及應用交付缺失（L2 —— Linux Server Administrations）。** 面向客戶的網頁層沒有反向代理，也沒有負載平衡，因此其發佈方式會暴露原始伺服器，且無法承受單一節點損失；第四項盡職審查條件 —— 面向客戶的網頁層具備有文件記錄的故障轉移行為 —— 完全無法達成。可從外部觸及的服務與內部系統處於同一區段，因此實際上並無任何有意義的非軍事區。出口流量未經過濾、亦無記錄，因此來自受感染工作站或已遭入侵伺服器的對外連線，與合法流量無法區分，且不留任何可歸屬的記錄。灣仔交付辦公室負責為第三方系統進行整合工作，卻與一般辦公室流量經同一路徑連接總部，既無獨立加密隧道，亦無將整合區段與生產憑證分隔的最大特權限制。整個資產的憑證均為自我簽署並以人手續期，因此憑證到期是由服務中斷才被發現。

**網絡及路由缺失（L3 —— Cisco Networking）。** 總部與分支辦公室之間沒有動態路由。澳門辦公室運行與公司其餘部分不同的路由網域，而兩者之間的邊界從未經刻意設計，因此一個設定錯誤的公告便可能導致流量被黑洞化或形成迴圈。只有一條廣域網絡鏈路，且與中轉供應商沒有 BGP 關係，因此轉換至替代路徑是一項人手操作。在交換層，Spanning Tree 根橋從未經刻意選擇：根橋選舉取決於哪件硬件恰好最先啟動，而接取埠在沒有 PortFast、BPDU guard 或連接埠安全的情況下運行，使網絡暴露於橋接迴圈及未經授權裝置插入插座的風險。在周邊，DMZ 邊界並非由具備明確存取清單、NAT 規則及已檢查原則的防火牆所執行；而且沒有連接灣仔辦公室的站對站加密隧道。

**變更管理缺失（L4 —— Network Automation）。** 第五項盡職審查條件 —— 網絡變更須透過經審閱、可重複的設定套用 —— 目前無法滿足。交換機及防火牆變更是憑記憶以人手輸入，既不受版本控制，亦未經同儕審閱，且無法重現。用戶入職是一連串人手步驟，其完整性取決於管理員，而特權蔓延正是這樣開始的。目錄服務沒有自動化健康檢查，因此複寫失敗是用戶發現的。裝置設定沒有自動化盤點，因此公司無法證明其在任何過去日期的網絡設定為何 —— 這是經紀審計中最常見的單一要求。

**營運可視性缺失（L5 —— AI Network Management）。** 沒有集中監控、沒有日誌彙集，也沒有警示關聯。十八台虛擬機及十四台網絡裝置由五人使用個別主控台監看。真正到達的警示以無上下文的原始事件形式出現，因此具辨別性的工作 —— 判斷一連串認證失敗是表示用戶端設定錯誤、憑證過期，還是真正的憑證攻擊 —— 須在時間壓力下憑記憶完成。正是這項缺失促成項目第五條、亦最具探索性的工作流：一個提供建議、嚴格唯讀的代理，負責蒐集證據並草擬分流備註，同時把所有決定及所有變更留給人類管理員。

### 1.3 五條技術線的理據

這五條線並非任意羅列；它們是同一個業務問題必須獲得解決的五個層次，而題目單張正是基於這個理由將它們歸為一組。逐一審視，每條線都是一項技術練習。綜合審視，它們構成能滿足客戶五項合約條件的最低限度連貫系統。

這種連貫性雙向運行。身分（L1）是授權所依賴的基礎；網絡（L3）是承載其他每條線流量、並執行哪個區域可與哪個區域通訊的傳輸層；Linux 應用層（L2）是面向客戶服務實際所在之處，也是已發佈服務與內部服務之間界線所在之處；自動化（L4）是將設定轉化為經審閱、可重現成果物而非按鍵記憶的關鍵；而 AI 維運線（L5）則是對「五人團隊如何監看如此規模資產」這一問題的實際答案。移除任何一條線，都會有一項盡職審查條件無法滿足：沒有 L1 就沒有最大特權限制的聲稱，沒有 L2 就沒有有文件記錄的網頁層故障轉移，沒有 L3 就沒有隔離或受控的據點間路由，沒有 L4 就沒有經審閱的變更流程，而沒有 L5 則使上述一切得以持續的營運負擔未獲處理。

這些線在技術上亦互相依賴，這正是本項目成為單一工程作品、而非五份平行課業的原因。遙距存取方案以憑證為基礎，因此同時需要 Windows 憑證授權單位（L1）及 Linux TLS 材料（L2）；出口過濾器（L2）之所以有意義，僅因路由設計（L3）使它成為由內部區域通往互聯網的唯一路徑；自動化手冊（L4）同時設定 Linux 資產及 Windows 資產，並將 Cisco 設定收集為檔案；而代理（L5）則消耗監控堆疊所產生的遙測資料，並讀取 L1 所設定的同一套審計原則。這種相互依賴是刻意的設計特性，也是本計劃書呈現一個含五條技術線的環境、而非五項獨立交付成果的原因。

### 1.4 WorldSkills 情境

WorldSkills International 發佈職業標準（WSOS），訂明某一職業角色中支撐國際最佳實務的知識、理解、技能及能力。這些標準用以描述該職業對行業及企業實際代表的內容，而在技能競賽中，知識與理解的評估是透過表現評估進行，而非透過獨立的筆試。對畢業專題項目而言，這種取向具決定性：它獎勵一個能在評審員面前建置、操作、破壞並修復、並有證據支持的環境，而不是一個僅以圖表形式存在的環境。

本單元所用的題目單張明確引用此職業的職業標準 *IT Network Systems Administration*，而該標準的 2026 版發佈於：

```text
https://worldskills.org/what/projects/wsos/2026/events/611/skills/2447/
```

該頁面確認版本為 **WorldSkills Shanghai 2026**，技能名稱為 **IT Network Systems Administration**（技能 2447），並在頁腳載有時間戳 **Last updated: 02.06.2026 13:34 (GMT)**。其評估結構包括六個加權部分，合計 100%，而本項目的研究資料集記錄該六個部分共有 131 條要求行（普查：`proposal\research\wsos-2026-2447.md` 第 3.7 節及附錄 A）。本計劃書中所有關於該標準包含及不包含什麼的陳述，均取自本項目儲存庫內該頁面的機器驗證摘錄；該摘錄成功擷取該頁面，並逐字重新核對每一條引述的要求行與所擷取來源一致。該標準在本計劃書中通篇以三種特定方式使用：作為評估加權的來源，以支持項目將努力投入何處；作為逐字要求行的來源，以支持個別技術選擇；以及作為文件集品質及可追溯性的參考框架。

有一項限定必須在開首說明，因為本計劃書的誠信取決於此。WSOS 2026 是本項目的**參考框架**，而非用以認證本項目的合規標準。本項目並未聲稱取得 WorldSkills 認證、符合性或認可，亦未將 WSOS 呈列為監管義務。它使用該標準來回答一個更狹窄、更站得住腳的問題：本項目所做的工作是否發展該職業國際標準所述的勝任能力，且大致符合該標準本身為它們所分配的比重？第 4 節以逐範疇對應及明確披露標準保持沉默之處來回答該問題。

### 3.1 範圍之內

以下五條技術線界定本項目的技術邊界。它們先按題目單張的命名方式原文重現，包括單張本身的用語及拼寫：

就以上用語，此處記錄兩點說明，以免日後讀者誤以為屬編輯疏忽。題目單張在其 Linux 一行將隧道技術寫作「Wireguard」；該產品本身的名稱為 WireGuard，本計劃書在討論產品本身時使用「WireGuard」，而單張的拼寫僅出現於引述單張的內容之中。單張亦將目錄服務寫作「ADDS」，本計劃書在首次使用時將其展開為 Active Directory Domain Services（ADDS），其後沿用單張的形式。「包括但不限於」一語對範圍具重要意義：這五份清單屬示例性質，因此第 3.2 節明確說明本項目另行承擔哪些技術，以及拒絕哪些技術。

以下各小節說明實際將會實施的技術，以及構成實施的具體工作。

#### 3.1.1 L1 —— Microsoft Server Networking and Network Services

將會實施 Active Directory Domain Services（ADDS）、File Server Resource Manager（FSRM）、iSCSI、Routing and Remote Access Service（RRAS）及 IKEv2，並連同設計所需的支援角色。

- **ADDS：** 一個樹系、一個網域及一個樹狀目錄（`vertexpeak.fyp.lab`，NetBIOS `VERTEXPEAK`，功能等級 Windows Server 2025）；總部兩台可寫入網域控制站，具備目錄整合 DNS、DHCP 及 Active Directory Certificate Services；觀塘分支一台唯讀網域控制站；一個四據點的 Active Directory 據點拓撲，將每個子網路對應至一個據點；以及一套完整的組織單位結構，涵蓋使用者、電腦、群組、服務帳戶、管理員、網絡物件及隔離區。
- **FSRM：** 按共用資料夾套用的配額範本、至少一個具阻擋式檔案篩選的檔案群組、儲存報告，以及實際配額超額及實際被封鎖寫入的證據。
- **iSCSI：** 一台 iSCSI 目標伺服器，經專用儲存網絡呈現三個 LUN（20 GB、40 GB 及 60 GB 精簡配置），按發起程式啟用 challenge-handshake 認證，並由平台層附加及掛載該等 LUN。
- **RRAS：** Routing and Remote Access Service 角色提供遙距存取 VPN，並由 Network Policy Server 擔任 RADIUS 授權及計費服務。
- **IKEv2：** 使用機器及使用者憑證的憑證認證 IKEv2 遙距存取，設計上禁止使用預共享金鑰 IKEv2，並停用分割隧道。
- **設計所需的支援角色：** 具正向及反向區域的 Active Directory 整合 DNS，為模擬公開命名空間設定條件式轉送，並向每個用戶端推送備援解析器；具負載平衡故障轉移合作夥伴關係的 DHCP，並在每個閘道設轉送代理；以網域控制站為樹系來源的網絡時間同步；簽發內部公鑰基礎架構的憑證服務；適用於工作站、成員伺服器、非軍事區及網域控制站的群組原則基線；具 DFS 複寫目標的檔案共用；以及一部特權存取工作站作為管理進入點。

#### 3.1.2 L2 —— Linux Server Administrations

將會實施 Nginx、Keepalived、nftables、OpenVPN 及 WireGuard，並連同設計所需的支援 Linux 服務。

- **Nginx：** 一對位於非軍事區的反向代理，負責終止 TLS 並重新加密至應用層，發佈入口網站及網誌名稱，具備上游池、強化 TLS 原則及有文件記錄的憑證鏈；內容節點上另有配搭 PHP-FPM 及 MariaDB 的 Nginx。
- **Keepalived：** 兩對獨立 VRRP —— 一對在出口過濾器配對上，一對在反向代理配對上 —— 各具浮動虛擬位址、優先順序、搶佔及不僅測試介面而是測試服務的健康檢查，並各以所擷取的故障轉移作示範。
- **nftables：** 單一 inet family 規則集，具預設拒絕的 input 及 forward 原則、狀態式連線追蹤、受信任對等端的位址集、對外介面上的偽裝、防濫用的連線限制、每次丟棄前的日誌前綴，以及一個帶回滾計時器的原子式套用指令碼，使錯誤的規則集不會把團隊鎖在遙距主機之外。
- **OpenVPN：** 一套完整 TLS 虛擬私人網絡，具備以 Easy-RSA 建立的自家憑證授權單位、逐用戶端設定、傳輸強化、僅限於實際所需前綴的推送路由、已停用的重複用戶端支援，以及一項顯示已撤銷用戶端連線失敗的撤銷測試。
- **WireGuard：** 一套現代隧道實施，使用核心內模組，具備逐對等端金鑰、受限的允許前綴（站對站對等端絕不使用預設路由）、受限的 keepalive 行為，以及排除於版本控制之外的金鑰材料。
- **設計所需的支援 Linux 工作：** 套用於每台 Linux 客體的強化 Ubuntu 伺服器基線（核心參數、SSH 限制、無人值守安全更新、審計守護程序）；一套監控及日誌彙集堆疊；自動化控制節點及版本控制伺服器；一部非軍事區跳板主機，作為進入該區域的唯一管理路徑；以及異機設定及證據備份。

#### 3.1.3 L3 —— Cisco Networking

將會在 Cisco Packet Tracer 中實施 BGP、OSPF、EIGRP、RSTP 及 ASA 周邊防火牆。

- **OSPF：** 總部與觀塘分支之間單一區域 0，核心鏈路啟用認證、朝向接取埠的介面設為被動，並在邊緣產生預設資訊。
- **EIGRP：** 經典模式，自治系統 100，用於澳門辦公室及一段舊有中轉區段，管理距離保持預設值，並明確說明此依賴關係。
- **受控重新分佈：** 恰好一個重新分佈點，以路由標籤區分兩個路由網域，並按前綴集單向重新分佈，使重新分佈不會形成迴圈；設計禁止相互的無標籤重新分佈。
- **BGP：** 企業邊緣與模擬中轉供應商之間的基本外部 BGP，另有通往替代供應商的第二個工作階段，入向設前綴過濾、出向設路徑操控、設最大前綴防護、示範本地優先值，以及在主要工作階段關閉時所擷取的故障轉移。
- **RSTP：** Rapid Spanning Tree Protocol 覆蓋整個總部交換層，明確選擇主要及次要根橋，接取埠設 PortFast 及 BPDU guard，預期根埠設 root guard，並將所擷取的拓撲變更及收斂序列呈列為模擬行為，而非真實世界計時。
- **ASA：** 周邊防火牆作為非軍事區邊界，具備安全等級、物件群組、實現信任邊界規則的存取清單、動態及靜態位址轉換、針對設計允許協定的檢查原則、記錄至中央日誌接收器，以及一條連接灣仔辦公室、使用 IKEv2 的站對站 IPsec 隧道。
- **設計所需的支援網絡工作：** 具備 VLAN、主幹及供未使用埠使用的黑洞 VLAN 之三層交換拓撲；總部的 HSRP 閘道備援；HSRP 與 Linux VRRP 實施的第一跳備援比較；連接埠安全及 DHCP snooping；以及一項模擬語音服務，以承載辦公室電話 VLAN。

#### 3.1.4 L4 —— Network Automation

將會實施 PowerShell scripting、Ansible Playbook 及 Bash shell scripting，並連同使它們具意義的版本控制實務。

- **PowerShell scripting：** 至少五個指令碼，涵蓋新員工入職（以單一冪等操作完成帳戶、群組成員資格、主目錄及儲存分配）、目錄健康報告（將複寫、操作主機角色、名稱解析、原則磁碟區及時間偏差匯出為報告）、網絡裝置設定備份、服務矩陣的可執行端點測試，以及原則物件備份 —— 並由一個共用的受版本控制模組及每次執行一份日誌支援。
- **Ansible Playbook：** 至少九個手冊，具備可重用角色、涵蓋 Linux、Windows、非軍事區、網絡裝置、AI 及管理群組的清單、環境的群組變數、用於產生設定的 Jinja2 範本、從同一控制節點同時支援經 SSH 的 Linux 及經 WinRM 的 Windows，以及為每個手冊執行一次 check mode。
- **Bash shell scripting：** 至少五個指令碼，涵蓋強化基線、具備回滾的原子式防火牆套用、故障轉移驗證、備份，以及憑證到期檢查及續期，並具備一個實現記錄及嚴格錯誤處理的共用函式庫。
- **版本控制及審閱：** 一個 Git 儲存庫，採每項工作一個分支、具標籤的發行版本、記錄於會議記錄中的每項自動化變更兩人審閱、每次發行前的密鑰掃描，以及已提交的執行日誌。
- **Cisco 層的設定即程式碼：** 預定的裝置設定以檔案形式保存於同一儲存庫，使網絡設定具有可供審閱的真實來源，即使模擬器並無對外工具可觸及的管理介面亦然。此限制及其所需的雙軌處理方式載於範圍以外及限制的內容之中，而非被隱藏。

#### 3.1.5 L5 —— AI Network Management

將會在專用 Linux 客體上，以有限度概念驗證的形式實施 Agentic AI、OpenClaw Skills 及兼容 Model Context Protocol 的工具介面。

- **Agentic AI：** 一個代理執行環境，可接受警示或排程觸發，最多調用四項已聲明的唯讀工具，並產出含證據引用的分流備註，以及以差異形式呈現的*建議*設定變更。它絕不套用變更。
- **OpenClaw Skills：** 一個由四份清單組成的技能介面 —— 警示分流、介面健康、認證失敗報告及文件草擬 —— 並在依賴該線之前，先於有時限的可行性驗證中實際確定執行環境的版本、能力及技能格式。
- **Model Context Protocol (MCP)：** 唯讀工具介面定義為兼容 MCP 的工具定義，使其在有或沒有特定代理執行環境的情況下均可使用，並引註小組實際閱讀的規格。
- **防護措施：** 唯讀憑證不獲授予任何其他權限；除該帳戶外不儲存任何裝置憑證；每次調用均記錄提示雜湊及所進行工具調用的清單；對工具調用設硬性速率限制；網絡路徑僅可觸及設計允許的管理連接埠；且輸出一律標明為建議並須經人手批准。
- **已聲明的替代方案：** 若指定的執行環境無法安裝或評估，將建置一個實施相同四工具介面的等效通用代理迴圈，並報告該替換；若完全無法取得語言模型存取，則只示範確定性收集器、關聯規則及報告產生器，並將代理架構保留為設計工作，同時明確說明已縮減的示範範圍。

### 3.5 範圍管理

範圍是受控的，而非僅是寫下來的。共適用五項機制。

1. **單一的標準設計基線。** 每一個主機名稱、位址、VLAN 識別碼、軟件版本、路徑及命名慣例均在開始撰寫之前固定於一份受版本控制的基線文件之中。當某項交付成果需要一個數值時，它從該文件取得該數值，任何撰寫者均不得在本地偏離。該基線本身亦受版本控制，並以正式方式修訂，而非非正式編輯。
2. **為每項候選項目設定優先級別。** 每項均分類為必須、應該、可以或不會。「必須」級別 —— 核心 Windows 角色、OSPF、Spanning Tree 及周邊工作、具故障轉移的代理及出口過濾器，以及最少三項自動化成果物 —— 優先獲得保護，而「應該」及「可以」級別只有在上一級別已取得證據後才會開始。
3. **正式的變更請求途徑。** 任何擬對範圍作出的增補或刪減，均須在每週檢討中提出，連同其對時間、風險及相依關係的影響記錄於決定日誌，並僅在四名成員中至少三人同意且指導老師知悉的情況下獲接納。獲接納的變更須先反映於時間表及基線之中，工作方可繼續。
4. **技術凍結。** 第九週之後不得加入新技術。餘下週數保留作測試、取證、結案及撰寫。此規則存在的原因，是此等廣度項目最可能的失敗原因，就是在第十週開始做第七件有趣的事。
5. **每次發行均作可追溯性檢查。** 在每個帶標籤的發行版本之前，可追溯性矩陣均會重新產生並檢查兩種失效模式：題目單張所列但沒有設計章節及測試個案的技術，以及聲稱已交付但沒有證據引用的技術。任何一項發現均會阻擋發行。同一清掃亦會移除任何潛入「我們已實施的項目」清單中的已排除技術，使已建置與未建置之間的界線，在四人編輯報告的過程中始終保持誠實。

計劃中的刪減遵循同一紀律的反向做法。當某項目被剔除 —— 最可能是可選的第二層憑證授權單位、語音服務，或某項個別 AI 能力 —— 該剔除均連同理由記錄，受影響的報告章節予以修正，而該項目會移至未來工作，而非從記錄中刪除。

## 4. 標準及合規對應

### 4.1 參考標準

本項目的參考標準，是技能 **IT Network Systems Administration** 的 **WorldSkills Occupational Standards 2026**。題目單張本身在其參考行中亦正是引用此標準：

> Reference: IT Network Systems Administration, WorldSkills Occupational Standards 2026

該標準由 WorldSkills International 發佈，並自稱為 **WorldSkills Shanghai 2026** 版。本計劃書所涵蓋的版本僅為 2026 版。題目單張在同一參考行中提供該標準的位置，該位址已於來源獨立核對，而該標準的確切位置為：

```text
https://worldskills.org/what/projects/wsos/2026/events/611/skills/2447/
```

該標準本身的頁腳載有時間戳 **Last updated: 02.06.2026 13:34 (GMT)**，而該頁面的標題為 *WorldSkills Occupational Standards - IT Network Systems Administration*。其評估結構由六個加權部分及一個合計列組成，全文在該六個部分中共有 **131 條要求行**，此據本項目研究資料集本身的普查（`proposal\research\wsos-2026-2447.md` 第 3.7 節及附錄 A）。本計劃書中所有關於該標準內容的陳述，均取自保存於本項目儲存庫內該頁面的機器驗證摘錄（`proposal\research\wsos-2026-2447.md`），其中該頁面成功擷取，且每一條所摘錄的要求行均逐字與所擷取來源重新核對，並無任何不符。

該標準本身的一般說明解釋此結構如何運用：標準訂明支撐技術及職業表現國際最佳實務的知識、理解、技能及能力；標準劃分為具標題及參考編號的不同部分；而*「每個部分均獲分配總分的某個百分比，以顯示其在標準中的相對重要性。這通常稱為『加權』。所有百分比分數的總和為 100。加權決定評分方案內分數的分佈。」* 知識與理解的評估透過表現評估進行，其載體為由評分方案評定的 Test Project。

### 4.4 AI Network Management 線

AI Network Management 線是本項目中唯一在參考標準內獲得**零涵蓋**的技術線。此點明確說明，因為另一做法 —— 暗示代理式 AI 網絡管理屬 WorldSkills 要求 —— 將屬虛假，且只需在已發佈頁面上搜尋一次即可被推翻。經核實的立場如下。

- 2026 標準在其可見文字及原始標記中，**均沒有出現** `Agentic`、`OpenClaw`、`MCP`、`Model Context Protocol`、`artificial intelligence` 或 `machine learning`。
- 2024 版同樣如此：這並非近期移除，而是該技能已發佈標準中的真實缺席。
- 就「AI」兩個字母作粗略搜尋確實會在頁面上得出結果，但**每一個都是子字串假陽性** —— 這兩個字母只是偶然出現於 *Shanghai*、*daily*、*maintain* 及 *domain* 等字詞之內（即 Sh-ai-nghai、d-ai-ly、m-ai-ntain、dom-ai-n）。它們均非 AI 內容的證據，本項目亦不如此引述。
- 2026 標準的自動化範疇佔 15%，是以指令碼自動化例行基礎架構維護，以及將基礎架構定義為程式碼。它並不是、亦不聲稱是營運*決策*的自動化。

因此該線定位為**超越標準的項目創新**，其理據緊扣標準本身的範疇 1（Work organization and management，5%）專業特質要求。有四行逐字引文承載該理據：

> `The speed of IT systems change and the need to maintain currency.`

> `Use thorough and efficient research methods to support knowledge growth`

> `Be enthusiastic to try new methods, systems, and embrace change`

> `The value of managing own continuing professional development`

綜合閱讀，這些句子描述的是一項獨立於任何特定技術的專業義務：資訊科技網絡系統管理員須跟上一個變化迅速的領域、透徹研究新方法，並願意嘗試在其現有工具組被選定時尚未存在的系統。網絡維運中的代理式協助正是該變革的當前前沿。因此本項目的聲稱是有關範疇 1 之下*專業行為*的聲稱 —— 小組妥善研究了新興領域、誠實地界定其範圍、建置了具安全防護措施的可用成果物，並報告了哪些有效、哪些無效 —— 而**並非**聲稱該標準要求或評估代理式 AI。本項目本身的可追溯性記錄將此線分類為沒有直接範疇涵蓋。

有三項界限強化該框架的誠實性。第一，該線界定為**具已聲明範圍的概念驗證**：一個唯讀的建議介面、對其在何處有幫助及何處浪費時間的評估，以及包括任何假陽性或幻覺在內的已記錄失效，其原則是以記錄失效比隱瞞失效為更強的學術成果。第二，該線設有**三條預先設計的替代路徑** —— 若指定執行環境無法評估，則使用等效的通用代理迴圈；若假定的格式證明有誤，則以執行環境的已記錄格式重新表述工具介面；若完全無法取得語言模型存取，則使用具腳本化原則的確定性關聯引擎 —— 使技術的失效不會變成項目的失效。第三，**不實施亦不聲稱任何自主修復**。本項目中沒有任何內容會在未經人手批准的情況下，向裝置、目錄服務或防火牆寫入變更，而該排除是基於安全及可重現性所作的設計決定，而非小組被迫接受的一項限制。
